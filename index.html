Recursos docentes

Cómo armar una actividad digital
paso a paso

Sin editar código a mano: el Generador produce el HTML de la actividad y el Code.gs listos para descargar y publicar.

1¿Cómo funciona el sistema?

Dos archivos que trabajan juntos: uno que corre en el navegador del alumno, otro que guarda las respuestas en Google Sheets.

Archivo del alumno
actividad.html

Se publica en la web (GitHub Pages u otro servicio). El alumno lo abre en el navegador, responde en pantalla completa y envía.

Script del docente
Code.gs

Se pega en Google Apps Script, se publica como Web App. Recibe las respuestas y las guarda en una Google Sheet.

Herramienta de armado
Generador

Un archivo HTML que corre localmente. Permite armar la actividad de forma visual y descarga los dos archivos anteriores listos para usar.

Almacenamiento
Google Sheets

Cada envío agrega una fila nueva con marca de tiempo, nombre del alumno, respuestas y corrección automática.

ArchivoDónde vive
actividad.html GitHub Pages (o cualquier servidor web)
Code.gs Google Apps Script (dentro de Google Drive)
Google Sheet Google Drive
Generador Tu computadora (o en la web — ver pestaña 2)
Flujo general Abrir el Generador → cargar las preguntas → descargar Code.gs → crear planilla y publicar Web App → copiar la URL → pegarla en el Generador → descargar la actividad.html → publicarla en la web (GitHub Pages u otro servicio).

2El Generador

Un archivo HTML que corre en el navegador: no requiere instalar nada.

Abrir el Generador ↗

O descargarlo desde GitHub para usar sin conexión.

1
Abrir el Generador

Hacer clic en el botón de arriba para abrirlo directamente en el navegador. También se puede descargar y abrir como archivo local — funciona igual en los dos casos.

2
Completar la sección Configuración

Título de la actividad, materia, instrucción inicial, cabecera de sección, tiempo en minutos y nombre del archivo que se va a descargar. La clave localStorage y la URL del Web App se completan más adelante.

3
Cargar las preguntas

Usar los botones + Opción múltiple, + V / F, + Abierta, + Emparejar y + Banco de palabras. Cada pregunta se edita, reordena y elimina desde su propio panel desplegable.

Cada vez que se usa El Generador trae preguntas de ejemplo para mostrar los tipos disponibles. Para empezar una actividad nueva, basta con cambiar la configuración y eliminar o reemplazar esas preguntas.

3Cargar las preguntas

Seis tipos disponibles, cada uno con su panel de edición.

TipoCuándo usarloCorrección
Opción múltiple 4 opciones, una sola correcta. Bueno para conceptos y definiciones. Automática — se elige la letra correcta en el panel.
Múltiple respuesta 4 opciones donde pueden ser correctas una o varias. El alumno marca todas las que corresponden con casillas de verificación. Automática (todo o nada) — se marcan en el panel las letras correctas; el alumno debe seleccionarlas todas y ninguna de las incorrectas para obtener el puntaje.
V / F Afirmación que el alumno marca como verdadera o falsa. Automática — se elige Verdadero o Falso en el panel.
Abierta Desarrollo, demostración o justificación. El alumno escribe con texto enriquecido y símbolos matemáticos. Manual — el texto queda guardado en la planilla para corregir a mano.
Emparejar El alumno conecta elementos de una columna izquierda con los de una columna derecha. Ideal para relacionar conceptos, términos con definiciones, o elementos de conjuntos. Automática con crédito parcial — se puntúa en proporción a los pares correctos (ej. 3/4 pares = 75% del puntaje).
Banco de palabras Texto con espacios en blanco que el alumno completa eligiendo palabras de un banco. En el panel se escribe el texto con las respuestas entre corchetes: [respuesta]. Se pueden agregar palabras distractoras opcionales. Automática con crédito parcial — se puntúa en proporción a los blancos completados correctamente.
Agregar una imagen a una pregunta Cada pregunta tiene un botón 📷 Imagen. Al hacer clic se abre el selector de archivos; la imagen se convierte automáticamente a formato digital y queda embebida en el HTML generado, sin necesidad de subirla a ningún servidor. La actividad sigue siendo un único archivo autocontenido. Para quitarla, usar la ✕ que aparece junto a la miniatura.
Generar preguntas con IA e importarlas de golpe El Generador incluye un botón ↓ Importar desde JSON que carga todas las preguntas a la vez. En lugar de escribirlas una por una, se le pide a la IA que las genere directamente en el formato JSON esperado, se copia el bloque y se pega en el importador.

Cómo hacerlo

1
Pedir el JSON a la IA

Usar este prompt (adaptando tema, curso y cantidad):

Prompt para la IA 
Generame un array JSON con preguntas para una actividad digital de [TEMA], para [CURSO].
Incluir: 3 de opción múltiple, 1 de múltiple respuesta, 2 de verdadero/falso, 1 abierta, 1 de emparejar y 1 de banco de palabras.
Usar exactamente este formato — sin texto adicional fuera del array:

[
  {
    "type": "single",
    "text": "Enunciado de la pregunta",
    "opts": ["Opción A", "Opción B", "Opción C", "Opción D"],
    "correct": "a"
  },
  {
    "type": "multi",
    "text": "¿Cuáles de las siguientes son propiedades de los conjuntos? (Seleccionar todas las correctas.)",
    "opts": ["Propiedad A", "Propiedad B", "Propiedad C", "Propiedad D"],
    "correct": ["a", "c"]
  },
  {
    "type": "tf",
    "text": "Enunciado para verdadero o falso.",
    "correct": "true"
  },
  {
    "type": "open",
    "text": "Enunciado de la pregunta abierta."
  },
  {
    "type": "match",
    "text": "Relacionar cada elemento con su correspondiente.",
    "pairs": [
      { "left": "Elemento izquierda 1", "right": "Elemento derecha 1" },
      { "left": "Elemento izquierda 2", "right": "Elemento derecha 2" },
      { "left": "Elemento izquierda 3", "right": "Elemento derecha 3" }
    ]
  },
  {
    "type": "fill",
    "text": "El [conjunto vacío] se denota con el símbolo [∅] y no contiene ningún [elemento].",
    "extraWords": "subconjunto, ℕ, intersección"
  }
]

Reglas:
- "correct" en opción múltiple (type "single"): "a", "b", "c" o "d". En V/F: "true" o "false".
- "correct" en múltiple respuesta (type "multi"): un array con todas las letras correctas, ej: ["a", "c"].
- "pairs": array de objetos {left, right} con los pares correctos. La columna derecha se muestra desordenada.
- "fill": las respuestas correctas van entre corchetes en el texto: [así]. "extraWords" son palabras distractoras (opcionales), separadas por coma.
- Se puede agregar "puntaje": 2 a cualquier pregunta para darle más peso.
2
Copiar el bloque JSON que devuelve la IA

Seleccionar solo el array (desde [ hasta ]), sin texto introductorio.

3
Importar en el Generador

Ir al Generador → sección Preguntas → clic en ↓ Importar desde JSON → pegar → clic en Importar preguntas. Las preguntas aparecen todas de inmediato.

4
Revisar y ajustar

Editar texto, puntajes u opciones que la IA no haya generado exactamente como se quería. Las preguntas abiertas que dependan del contexto específico de clase conviene escribirlas o modificarlas a mano.

Campos opcionales en el JSON Se puede agregar "puntaje": 2 para asignar más peso a una pregunta, y "obligatoria": false para marcarla como opcional. En preguntas de tipo fill, "extraWords" agrega palabras distractoras al banco. En preguntas de tipo multi, "correct" es un array con todas las letras correctas: ["a", "c"]. Si se omiten los opcionales, el Generador usa los valores por defecto (1 punto, obligatoria, sin distractores).

Símbolos matemáticos en preguntas abiertas

Las preguntas de tipo Abierta incluyen automáticamente una barra de herramientas con símbolos matemáticos y formato. El alumno los inserta con un clic, sin necesidad de teclado especial. Los símbolos disponibles cubren distintas áreas:

  • Conjuntos: ∈ ∉ ⊆ ⊂ ∪ ∩ − △ ᶜ ∅
  • Conjuntos numéricos: ℕ ℤ ℝ ℚ
  • Comparación: ≤ ≥ ≠ ≈ ≡
  • Operadores: × ÷ ± √ ∑ ∏ ∞
  • Lógica: ∧ ∨ ¬ → ↔ ∀ ∃
  • Formato: negrita, cursiva, subrayado, tamaño de letra
Clave localStorage Cada actividad necesita una clave única en el campo Clave localStorage (ej. logica_conjuntos_2026, logica_grafos_2026). Si dos actividades distintas usan la misma clave y el alumno ya hizo la primera, la segunda le va a aparecer como "ya enviada". Conviene incluir el tema y el año.

4Planilla y Code.gs

El script que recibe las respuestas y las guarda en Google Sheets.

1
Descargar el Code.gs desde el Generador

En el Generador, una vez cargadas las preguntas, hacer clic en ⬇ Descargar Code.gs. Se descarga un archivo de texto con el script ya configurado para esa actividad.

2
Crear una Google Sheet nueva

En Google Drive: Nuevo → Google Sheets. Darle un nombre relacionado con la actividad, por ejemplo Respuestas – Conjuntos 2026.

3
Abrir el editor de Apps Script

En la planilla: menú Extensiones → Apps Script. Se abre el editor con un archivo Code.gs vacío.

4
Pegar el código descargado

Borrar todo el contenido del editor, pegar el contenido del archivo Code.gs descargado y hacer clic en Guardar (ícono del diskette o Ctrl+S).

No hacer clic en Ejecutar El botón Ejecutar del editor sirve para probar funciones manualmente. La función doGet espera un parámetro que solo llega cuando un alumno envía la actividad, así que ejecutarla a mano da error. No es necesario ejecutar nada: el script se activa solo cuando recibe un envío.

5Publicar como aplicación web

Este paso convierte el script en una URL que la actividad puede llamar para guardar respuestas.

1
Implementar → Nueva implementación

En el editor de Apps Script: botón azul Implementar (arriba a la derecha) → Nueva implementación.

2
Configurar la implementación

En el diálogo que aparece:
— Tipo: Aplicación web (ícono de engranaje → seleccionar si no está)
— Ejecutar como: Yo
— Quién tiene acceso: Cualquier usuario
Hacer clic en Implementar.

3
Autorizar el acceso

La primera vez pide autorización. Hacer clic en Autorizar acceso → elegir la cuenta de Google → en la pantalla de advertencia, clic en Avanzado → Ir a [nombre del proyecto] (no seguro) → Permitir.

4
Copiar la URL del Web App

Aparece una URL larga que empieza con https://script.google.com/macros/s/.... Copiarla — se necesita en el siguiente paso.

Permisos necesarios Al autorizar, el script pide permiso para leer y escribir en Google Sheets. Es necesario para que pueda crear los encabezados y agregar las filas de respuestas. El script solo accede a la planilla donde fue creado.
Si se modifica el script después Cada vez que se guarda un cambio en el Code.gs hay que hacer una nueva implementación (Implementar → Administrar implementaciones → Nueva versión). La URL no cambia, pero el código actualizado no entra en efecto hasta publicar la nueva versión.

6Pegar la URL en el Generador

Este es el dato que conecta la actividad con la planilla.

Volver al Generador y pegar la URL copiada en el paso anterior en el campo "URL del Web App de Google Apps Script". Ahora el Generador tiene todo lo que necesita para producir la actividad completa.

Si ya se descargó el Code.gs antes de tener la URL No hace falta volver a descargarlo: el Code.gs no cambia si se modifica la URL. La URL solo va adentro del actividad.html, que se genera en el paso siguiente.

7Generar y descargar la actividad

El Generador produce el HTML de la actividad con todo adentro: preguntas, estilos, lógica y URL de la planilla.

Hacer clic en ⬇ Descargar actividad.html. El archivo se descarga con el nombre configurado (por ejemplo actividad_conjuntos.html).

Qué lleva la actividad generada
  • Todas las preguntas con corrección automática para opción múltiple, V/F, emparejar y banco de palabras
  • Pantalla completa forzada al comenzar
  • Aviso visible si el alumno sale de pantalla completa
  • Anti-doble-envío: si el alumno reabre el archivo ya enviado, ve "Actividad enviada"
  • Barra de símbolos matemáticos en preguntas abiertas
  • Temporizador configurable
iPhone y iPad — pantalla completa En dispositivos iOS (iPhone e iPad), ningún navegador puede forzar la pantalla completa: Apple no lo permite. La actividad funciona con normalidad, pero sin ese modo. Si los alumnos usan celulares Apple, la restricción de pantalla completa no aplica para ellos.

Probar antes de distribuir

Abrir el archivo descargado y completarlo como lo haría un alumno:

  • Responder todas las preguntas y enviar.
  • Abrir la Google Sheet: debe haber aparecido una fila nueva con el nombre, las respuestas y el puntaje automático.
  • Cerrar y volver a abrir la actividad en el mismo navegador: debe mostrar "Actividad enviada" sin permitir responder de nuevo.
Reiniciar el anti-doble-envío para seguir probando Si se quiere volver a hacer la actividad desde el mismo navegador (para probar): presionar Fn + F12 (en algunos teclados alcanza con F12 solo) para abrir las herramientas de desarrollo → hacer clic en la pestaña Consola → escribir localStorage.clear() y presionar Enter → recargar la página. La actividad vuelve a la pantalla de inicio.
Próxima actividad Para armar la siguiente actividad de otra unidad: abrir el Generador, cambiar el título, la clave localStorage (¡obligatorio!) y las preguntas, y repetir desde el paso 4 si se usa una planilla nueva, o desde el paso 6 si se reutiliza la misma planilla con el mismo Web App.

8Publicar en GitHub Pages

Una URL pública y gratuita para que los alumnos accedan desde cualquier dispositivo.

1
Crear o usar un repositorio de GitHub

En github.com: New repository. Darle un nombre relacionado con la actividad, por ejemplo ActividadConjuntos. Dejarlo público.

2
Activar GitHub Pages

En el repositorio: Settings → Pages → Branch: main → Save. GitHub Pages queda habilitado para ese repositorio.

3
Subir el archivo HTML

Dentro del repositorio: Add file → Upload files. Subir el actividad_conjuntos.html. Hacer clic en Commit changes.

4
Esperar unos segundos y obtener la URL

La URL tiene el formato https://USUARIO.github.io/REPO/actividad_conjuntos.html. Si el archivo se llama index.html, alcanza con https://USUARIO.github.io/REPO/.

5
Compartir la URL con los alumnos

Por Google Classroom, correo o cualquier otro medio. Los alumnos la abren en cualquier navegador desde cualquier dispositivo.

Alternativa sin publicar La actividad funciona igual si se reparte como archivo (por Classroom, correo o pendrive) y el alumno lo abre directamente en el navegador. La conexión con la planilla funciona igual en los dos casos — no depende de dónde esté el HTML.

9Glosario

Términos técnicos que aparecen en la guía, explicados sin jerga.

Archivo HTML
Un archivo de texto con extensión .html que el navegador sabe cómo mostrar como una página web. Es el formato de la actividad digital y del Generador. No necesita instalarse ni compilarse: se abre directamente con doble clic, como un documento Word, pero en el navegador.
Google Apps Script
Un entorno de programación integrado en Google Drive que permite crear scripts que interactúan con Google Sheets, Gmail, Calendar y otros servicios de Google. En este sistema es el puente entre la actividad del alumno y la planilla de respuestas.
El Generador (generador_escritos.html)
Una herramienta hecha en HTML que funciona en el navegador. Permite armar la actividad de forma visual — sin tocar código — y descarga los dos archivos necesarios al terminar.
Web App / Aplicación web
Cuando el script se "publica", Google le asigna una dirección web (URL) a través de la cual puede recibir información. Esa URL es la que conecta la actividad con la planilla: cada vez que un alumno envía sus respuestas, la actividad llama a esa dirección y el script hace el resto.
URL
La dirección de una página web, como https://www.google.com. En este sistema se usa la URL del Web App (el script publicado) para que la actividad sepa a dónde enviar las respuestas.
Implementar (un script)
"Implementar" en el contexto de Apps Script significa publicar el script para que funcione como una aplicación web accesible desde internet. Es el equivalente a "poner en marcha" el script. Solo hace falta hacerlo una vez por actividad (o cuando se cambia algo en el script).
GitHub
Un sitio web donde se pueden guardar y compartir archivos de texto, código y páginas web. Es gratuito y ampliamente usado. En este sistema lo usamos para publicar la actividad en internet.
GitHub Pages
Un servicio gratuito de GitHub que convierte los archivos de un repositorio en una página web accesible con una URL pública. Es la forma más sencilla de publicar la actividad para que los alumnos puedan acceder desde cualquier dispositivo con internet.
Repositorio
Una "carpeta" dentro de GitHub donde se guardan los archivos de un proyecto. Cada actividad puede tener su propio repositorio, o varias actividades pueden convivir en uno.
JSONP
Una técnica que permite a una página web enviar datos a un servidor en otro dominio. En este sistema la actividad la usa para enviar las respuestas al script de Google sin errores de seguridad del navegador.
localStorage
Un pequeño espacio de memoria que el navegador reserva para cada página web. En este sistema se usa para recordar si un alumno ya envió la actividad: si la intenta abrir de nuevo en el mismo navegador y dispositivo, ve el mensaje "Actividad enviada" en lugar de las preguntas. No es un sistema de seguridad absoluto (borrando los datos del navegador se puede reiniciar), pero evita el doble envío accidental.
Clave localStorage
Un nombre interno que identifica a cada actividad dentro del navegador. Si dos actividades distintas usan el mismo nombre, el navegador las confunde y puede mostrar "ya enviada" al alumno que hizo la primera. Por eso cada actividad necesita una clave única, por ejemplo logica_fracciones_2026.
Pantalla completa forzada
Una función del navegador que oculta la barra de pestañas, la barra de direcciones y el resto de la pantalla, mostrando solo la actividad. En este sistema se activa al comenzar el examen y, si el alumno la cierra (por ejemplo, para abrir otra pestaña), la actividad se envía automáticamente con lo que haya contestado hasta ese momento.
Autocontenido
Un archivo que lleva todo adentro: estilos, lógica, preguntas. No depende de otros archivos ni de conexión a internet para mostrarse correctamente. La actividad generada es autocontenida, por eso funciona igual si se comparte por correo, pendrive o GitHub Pages.
Publicar la actividad
Subirla a un servidor web para que tenga una URL accesible desde cualquier dispositivo. La opción más usada aquí es GitHub Pages, pero también puede publicarse en Netlify, Vercel, el servidor del centro educativo, o simplemente repartirse como archivo.
