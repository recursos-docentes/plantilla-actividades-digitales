Recursos docentes

Cómo armar un escrito digital
paso a paso

Sin editar código a mano: el Generador produce el HTML del escrito y el Code.gs listos para descargar y publicar.

1Arquitectura del sistema

Dos archivos, cada uno en su lugar — así funciona la corrección automática sin exponer las respuestas.

El sistema funciona con dos piezas que viven separadas.

ArchivoDónde viveQué hace
escrito_TEMA.html GitHub Pages (o cualquier servidor web) El examen que abre el alumno: preguntas, pantalla completa forzada, anti-doble-envío. No contiene ninguna respuesta correcta.
Code.gs Apps Script vinculado a una Google Sheet Recibe cada intento, autocorrige y guarda la fila en la planilla. La clave de respuestas vive solo aquí.

El Generador produce ambos archivos con un clic — sin necesidad de editar código a mano.

Flujo general Abrir el Generador → cargar las preguntas → descargar Code.gs → crear planilla y publicar Web App → copiar la URL → pegarla en el Generador → descargar el escrito.html → publicarlo en la web (GitHub Pages u otro servicio).

2El Generador

Un archivo HTML que corre en el navegador: no requiere instalar nada.

El Generador es el archivo generador_escritos.html. Para usarlo:

1
Abrir el archivo en el navegador

Hacer doble clic en generador_escritos.html. Se abre como una aplicación web local — no necesita conexión a internet para funcionar.

2
Completar la sección Configuración

Título del escrito, materia, instrucción inicial, cabecera de sección, tiempo en minutos y nombre del archivo que se va a descargar. La clave localStorage y la URL del Web App se completan más adelante.

3
Cargar las preguntas

Usar los botones + Opción múltiple, + V / F y + Abierta. Cada pregunta se edita, reordena y elimina desde su propio panel desplegable.

Cada vez que se usa El Generador trae preguntas de ejemplo para mostrar los tipos disponibles. Para empezar una actividad nueva, basta con cambiar la configuración y eliminar o reemplazar esas preguntas.

3Cargar las preguntas

Cinco tipos disponibles, cada uno con su panel de edición.

TipoCuándo usarloCorrección
Opción múltiple 4 opciones, una correcta. Bueno para conceptos y definiciones. Automática — se elige la letra correcta en el panel.
V / F Afirmación que el alumno marca como verdadera o falsa. Automática — se elige Verdadero o Falso en el panel.
Abierta Desarrollo, demostración o justificación. El alumno escribe con texto enriquecido y símbolos matemáticos. Manual — el texto queda guardado en la planilla para corregir a mano.
Emparejar El alumno conecta elementos de una columna izquierda con los de una columna derecha. Ideal para relacionar conceptos, términos con definiciones, o elementos de conjuntos. Automática con crédito parcial — se puntúa en proporción a los pares correctos (ej. 3/4 pares = 75% del puntaje).
Banco de palabras Texto con espacios en blanco que el alumno completa eligiendo palabras de un banco. En el panel se escribe el texto con las respuestas entre corchetes: [respuesta]. Se pueden agregar palabras distractoras opcionales. Automática con crédito parcial — se puntúa en proporción a los blancos completados correctamente.
Generar preguntas con IA e importarlas de golpe El Generador incluye un botón ↓ Importar desde JSON que carga todas las preguntas a la vez. En lugar de escribirlas una por una, se le pide a la IA que las genere directamente en el formato JSON esperado, se copia el bloque y se pega en el importador.

Cómo hacerlo

1
Pedir el JSON a la IA

Usar este prompt (adaptando tema, curso y cantidad):

Prompt para la IA 
Generame un array JSON con preguntas para una actividad digital de [TEMA], para [CURSO].
Incluir: 4 de opción múltiple, 2 de verdadero/falso, 1 abierta, 1 de emparejar y 1 de banco de palabras.
Usar exactamente este formato — sin texto adicional fuera del array:

[
  {
    "type": "single",
    "text": "Enunciado de la pregunta",
    "opts": ["Opción A", "Opción B", "Opción C", "Opción D"],
    "correct": "a"
  },
  {
    "type": "tf",
    "text": "Enunciado para verdadero o falso.",
    "correct": "true"
  },
  {
    "type": "open",
    "text": "Enunciado de la pregunta abierta."
  },
  {
    "type": "match",
    "text": "Relacionar cada elemento con su correspondiente.",
    "pairs": [
      { "left": "Elemento izquierda 1", "right": "Elemento derecha 1" },
      { "left": "Elemento izquierda 2", "right": "Elemento derecha 2" },
      { "left": "Elemento izquierda 3", "right": "Elemento derecha 3" }
    ]
  },
  {
    "type": "fill",
    "text": "El [conjunto vacío] se denota con el símbolo [∅] y no contiene ningún [elemento].",
    "extraWords": "subconjunto, ℕ, intersección"
  }
]

Reglas:
- "correct" en opción múltiple: "a", "b", "c" o "d". En V/F: "true" o "false".
- "pairs": array de objetos {left, right} con los pares correctos. La columna derecha se muestra desordenada.
- "fill": las respuestas correctas van entre corchetes en el texto: [así]. "extraWords" son palabras distractoras (opcionales), separadas por coma.
- Se puede agregar "puntaje": 2 a cualquier pregunta para darle más peso.
2
Copiar el bloque JSON que devuelve la IA

Seleccionar solo el array (desde [ hasta ]), sin texto introductorio.

3
Importar en el Generador

Ir al Generador → sección Preguntas → clic en ↓ Importar desde JSON → pegar → clic en Importar preguntas. Las preguntas aparecen todas de inmediato.

4
Revisar y ajustar

Editar texto, puntajes u opciones que la IA no haya generado exactamente como se quería. Las preguntas abiertas que dependan del contexto específico de clase conviene escribirlas o modificarlas a mano.

Campos opcionales en el JSON Se puede agregar "puntaje": 2 para asignar más peso a una pregunta, y "obligatoria": false para marcarla como opcional. En preguntas de tipo fill, "extraWords" agrega palabras distractoras al banco. Si se omiten, el Generador usa los valores por defecto (1 punto, obligatoria, sin distractores).

Símbolos matemáticos en preguntas abiertas

Las preguntas de tipo Abierta incluyen automáticamente una barra de herramientas con símbolos matemáticos y formato. El alumno los inserta con un clic, sin necesidad de teclado especial. Los símbolos disponibles cubren distintas áreas:

  • Conjuntos: ∈ ∉ ⊆ ⊂ ∪ ∩ − △ ᶜ ∅
  • Conjuntos numéricos: ℕ ℤ ℝ ℚ
  • Comparación: ≤ ≥ ≠ ≈ ≡
  • Operadores: × ÷ ± √ ∑ ∏ ∞
  • Lógica: ∧ ∨ ¬ → ↔ ∀ ∃
  • Formato: negrita, cursiva, subrayado, tamaño de letra
Clave localStorage Cada actividad necesita una clave única en el campo Clave localStorage (ej. logica_conjuntos_2026, logica_grafos_2026). Si dos actividades distintas usan la misma clave y el alumno ya hizo la primera, la segunda le va a aparecer como "ya enviada". Conviene incluir el tema y el año.

4Crear la planilla y pegar el Code.gs

Primero la planilla, luego el script — en ese orden para que queden vinculados.

1
Descargar el Code.gs desde el Generador

En el panel derecho del Generador, hacer clic en ⬇ Descargar Code.gs. El archivo se descarga listo — no hace falta editarlo.

2
Crear una Google Sheet nueva

En Google Drive: Nuevo → Google Sheets. Darle un nombre descriptivo, por ejemplo Respuestas Conjuntos 2026. No hace falta escribir nada adentro — los encabezados los agrega el script solo cuando llega el primer envío.

3
Abrir Apps Script desde esa planilla

Menú Extensiones → Apps Script. Se abre el editor con un archivo Code.gs vacío.

4
Reemplazar el contenido y guardar

Seleccionar todo (Ctrl+A), borrar, pegar el contenido del Code.gs descargado. Guardar con Ctrl+S.

Por qué desde la planilla y no suelto El script usa getActiveSpreadsheet() para encontrar la hoja donde guardar las respuestas. Eso solo funciona cuando el script está vinculado a una planilla — lo que ocurre al crearlo desde Extensiones → Apps Script dentro de una Sheet. Si se crea un proyecto suelto en script.google.com, el script no encuentra ninguna hoja y no guarda nada.

5Publicar como aplicación web

Este paso convierte el script en una URL que el escrito puede llamar para guardar respuestas.

1
Implementar → Nueva implementación

Botón azul arriba a la derecha en el editor de Apps Script.

2
Configurar el tipo

Tipo: Aplicación web. Ejecutar como: Yo. Quién tiene acceso: Cualquier persona.

3
Autorizar

Google va a pedir permiso para ejecutar el script. El aviso de "aplicación no verificada" es normal — se trata de un script propio, no de una app de terceros. Hacer clic en Configuración avanzada → Ir a [nombre del proyecto] y aceptar.

4
Copiar la URL del Web App

Aparece en la sección App web, termina en /exec. Copiar esa URL — se necesita en el paso siguiente.

Para actualizar el Code.gs más adelante Si se modifica el script, guardar no alcanza. Hay que ir a Implementar → Administrar implementaciones → ✏️ editar → Nueva versión → Implementar. Crear una implementación nueva desde cero genera una URL distinta — conviene evitarlo porque habría que actualizar el HTML también.
No hacer clic en Ejecutar El botón Ejecutar del editor sirve para probar funciones manualmente. La función doGet espera un parámetro que solo llega cuando un alumno envía el escrito, así que ejecutarla a mano da error. No es necesario ejecutar nada: el script se activa solo cuando recibe un envío.

6Pegar la URL en el Generador

Este es el dato que conecta el escrito con la planilla.

Volver al Generador y pegar la URL copiada en el paso anterior en el campo "URL del Web App de Google Apps Script". Ahora el Generador tiene todo lo que necesita para producir el escrito completo.

Si ya se descargó el Code.gs antes de tener la URL No hace falta volver a descargarlo: el Code.gs no cambia si se modifica la URL. La URL solo va adentro del escrito.html, que se genera en el paso siguiente.

7Generar y descargar el escrito

El Generador produce el HTML del escrito con todo adentro: preguntas, estilos, lógica y URL de la planilla.

Hacer clic en ⬇ Descargar escrito.html. El archivo se descarga con el nombre configurado (por ejemplo escrito_conjuntos.html).

El archivo resultante es completamente autocontenido: CSS, JS y preguntas en un solo HTML. No depende de ninguna librería externa salvo la fuente de Google Fonts (que carga con internet).

Qué lleva el escrito generado
  • Pantalla de inicio con campo de nombre y apellido
  • Pantalla completa forzada al hacer clic en Comenzar
  • Auto-envío si el alumno sale de pantalla completa
  • Anti-doble-envío: si el alumno reabre el archivo ya enviado, ve "Escrito enviado"
  • Barra de símbolos matemáticos en preguntas abiertas
  • Pantalla de confirmación con autocorrección parcial de las preguntas cerradas

8Publicar en GitHub Pages

Para que los alumnos accedan con una URL, sin repartir el archivo.

1
Crear o usar un repositorio de GitHub

En github.com: New repository. Darle un nombre relacionado con el escrito, por ejemplo EscritoConjuntos. Dejarlo público.

2
Subir el archivo HTML

Dentro del repositorio: Add file → Upload files. Subir el escrito_conjuntos.html. Hacer clic en Commit changes.

3
Activar GitHub Pages

Settings → Pages → Source: Deploy from a branch → main / (root) → Save. En unos minutos el repositorio queda publicado.

4
Obtener la URL del escrito

La URL tiene el formato https://USUARIO.github.io/REPO/escrito_conjuntos.html. Si el archivo se llama index.html, alcanza con https://USUARIO.github.io/REPO/.

Solo el título visible — causa frecuente Si al abrir la URL de GitHub Pages solo se ve el título y nada más, casi siempre es porque se está accediendo a github.com/usuario/repo/blob/main/archivo.html (la vista de código fuente de GitHub) en vez de a la URL de GitHub Pages. La URL correcta empieza con USUARIO.github.io, no con github.com.
Alternativa sin publicar El escrito funciona igual si se reparte como archivo (por Classroom, correo o pendrive) y el alumno lo abre directamente en el navegador. La conexión con la planilla funciona igual en los dos casos — no depende de dónde esté el HTML.

9Probar y usar con alumnos

Siempre probarlo completo antes de usarlo en clase.

Abrir la URL del escrito y completarlo como lo haría un alumno:

  • Verificar que pide el nombre antes de empezar.
  • Verificar que solicita pantalla completa al hacer clic en Comenzar.
  • Responder todas las preguntas y hacer clic en Enviar respuestas.
  • Verificar que aparece la pantalla de confirmación con la autocorrección parcial.
  • Abrir la Google Sheet: debe haber aparecido una fila nueva con el nombre, las respuestas y el puntaje automático.
  • Cerrar y volver a abrir el escrito en el mismo navegador: debe mostrar "Escrito enviado" sin permitir responder de nuevo.
Reiniciar el anti-doble-envío para seguir probando Si se quiere volver a hacer el escrito desde el mismo navegador (para probar), hay que abrir las herramientas de desarrollo (F12) → pestaña Application → Local Storage → encontrar la clave del escrito (por ejemplo logica_conjuntos_2026) → eliminarla. Recargando la página, el escrito vuelve a la pantalla de inicio.
Próximo escrito Para armar el siguiente escrito de otra unidad: abrir el Generador, cambiar el título, la clave localStorage (¡obligatorio!) y las preguntas, y repetir desde el paso 4 si se usa una planilla nueva, o desde el paso 6 si se reutiliza la misma planilla con el mismo Web App.

★Glosario

Términos técnicos explicados sin tecnicismos — para docentes, no para ingenieros.

Archivo HTML
Un archivo de texto con extensión .html que el navegador sabe cómo mostrar como una página web. Es el formato del escrito digital y del Generador. No necesita instalarse ni compilarse: se abre directamente con doble clic, como un documento Word, pero en el navegador.
Navegador
El programa que usamos para entrar a internet: Chrome, Firefox, Edge, Safari. También puede abrir archivos HTML guardados en la computadora, sin necesidad de conexión a internet.
El Generador (generador_escritos.html)
Una herramienta hecha en HTML que funciona en el navegador. Permite armar el escrito de forma visual — sin tocar código — y descarga los dos archivos necesarios al terminar.
Script / Code.gs
Un "script" es un conjunto de instrucciones escritas en un lenguaje que la computadora ejecuta automáticamente. En este caso, Code.gs es el script que recibe las respuestas de los alumnos, las corrige y las guarda en la planilla. Vive dentro de Google, no en nuestra computadora.
Google Apps Script
Una plataforma de Google que permite escribir pequeños programas (scripts) vinculados a las herramientas de Google (Sheets, Docs, Forms, etc.). Es gratuita y viene incluida en cualquier cuenta de Google.
Aplicación web / Web App
Cuando el script se "publica", Google le asigna una dirección web (URL) a través de la cual puede recibir información. Esa URL es la que conecta el escrito con la planilla: cada vez que un alumno envía sus respuestas, el escrito llama a esa dirección y el script hace el resto.
URL
La dirección de una página web, como https://www.google.com. En este sistema se usa la URL del Web App (el script publicado) para que el escrito sepa a dónde enviar las respuestas.
Implementar (un script)
"Implementar" en el contexto de Apps Script significa publicar el script para que funcione como una aplicación web accesible desde internet. Es el equivalente a "poner en marcha" el script. Solo hace falta hacerlo una vez por escrito (o cuando se cambia algo en el script).
GitHub
Un sitio web donde se pueden guardar y compartir archivos de texto, código y páginas web. Es gratuito y ampliamente usado. En este sistema lo usamos para publicar el escrito en internet.
GitHub Pages
Un servicio gratuito de GitHub que convierte los archivos de un repositorio en una página web accesible con una URL pública. Es la forma más sencilla de publicar el escrito para que los alumnos puedan acceder desde cualquier dispositivo con internet.
Repositorio
Una "carpeta" dentro de GitHub donde se guardan los archivos de un proyecto. Cada escrito puede tener su propio repositorio, o varios escritos pueden convivir en uno.
Commit
La acción de confirmar y guardar cambios en un repositorio de GitHub. Es similar a hacer clic en "Guardar" en un documento, pero queda registrado con fecha y descripción.
localStorage
Un pequeño espacio de memoria que el navegador reserva para cada página web. En este sistema se usa para recordar si un alumno ya envió el escrito: si lo intenta abrir de nuevo en el mismo navegador y dispositivo, ve el mensaje "Escrito enviado" en lugar de las preguntas. No es un sistema de seguridad absoluto (borrando los datos del navegador se puede reiniciar), pero evita el doble envío accidental.
Clave localStorage
Un nombre interno que identifica a cada escrito dentro del navegador. Si dos escritos distintos usan el mismo nombre, el navegador los confunde y puede mostrar "ya enviado" al alumno que hizo el primero. Por eso cada escrito necesita una clave única, por ejemplo mate_fracciones_2026.
Pantalla completa forzada
Una función del navegador que oculta la barra de pestañas, la barra de direcciones y el resto de la pantalla, mostrando solo el escrito. En este sistema se activa al comenzar el examen y, si el alumno la cierra (por ejemplo, para abrir otra pestaña), el escrito se envía automáticamente con lo que haya contestado hasta ese momento.
Autocontenido
Un archivo que lleva todo adentro: estilos, lógica, preguntas. No depende de otros archivos ni de conexión a internet para mostrarse correctamente. El escrito generado es autocontenido, por eso funciona igual si se comparte por correo, pendrive o GitHub Pages.
Publicar el escrito
Subirlo a un servidor web para que tenga una URL accesible desde cualquier dispositivo. La opción más usada aquí es GitHub Pages, pero también puede publicarse en Netlify, Vercel, el servidor del centro educativo, o simplemente repartirse como archivo.
